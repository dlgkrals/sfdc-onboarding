### 2-5. 예약 작업이 있으면 해제 (재배포 때)

예약 작업이 참조하는 클래스(와 의존 클래스)는 "보류 중이거나 진행 중인 작업이 있습니다"로 **배포도, 검증 배포(validate)도 거부**된다. 클래스를 한 번에 배포하면 예약과 무관한 클래스까지 함께 거부된다. "Apex 작업이 있어도 배포 허용" 설정은 켜지 않는다.

| 예약 이름                                  | 실행 클래스                                             | 다시 등록                                                 |
| ------------------------------------------ | ------------------------------------------------------- | --------------------------------------------------------- |
| HG 반복 고장 재계산 (매일 02:00)           | AssetRepeatFailureSchedulable → AssetRepeatFailureBatch | `scripts/apex/d6_schedule.apex`                           |
| HG ERP 재전송 (매시 정각)                  | ErpRetrySchedulable                                     | `scripts/apex/d7_erp_retry_schedule.apex`                 |
| HG ERP 재고 동기화 :30 (매시, 푸시 안전망) | ErpStockSyncSchedulable                                 | `scripts/apex/d7_erp_inbound_schedule.apex`(APPLY = true) |

```apex
// 해제 (익명 Apex, 이름 확인 후)
for (CronTrigger ct : [SELECT Id, CronJobDetail.Name FROM CronTrigger WHERE CronJobDetail.Name LIKE 'HG %']) {
  System.abortJob(ct.Id);
}
```

- 익명 Apex 파일은 **BOM 없는 UTF-8**로 저장(PowerShell `Set-Content -Encoding UTF8`은 BOM을 붙여 조용히 실행 안 됨). 재등록 후 `CronTrigger` 3건 WAITING 조회

## 3. 배포 순서 (의존 관계)

한 번의 배포 안에서도 SFDX가 순서를 맞추지만, 환경 설정·데이터가 필요한 부분 때문에 단계로 나눈다. 운영 첫 배포는 **검증 배포 1회(전체) → 빠른 배포**가 기본이고, 실패 원인을 좁힐 때만 단계별로 나눈다.

| 단계 | 구분   | 구성 요소                                                                                                                                                                                                                                                           | 앞 단계가 필요한 이유                                                                                                                        |
| ---- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 기반   | GlobalValueSet `ServiceCenter` → 오브젝트·필드·레코드 유형·검증 규칙 → Custom Metadata 타입·레코드(ServiceSetting 11·WarrantyPolicy 3·ServiceCenterMapping 32·TriggerSetting 4) → Custom Setting → Custom Label → 사용자 지정 권한 → objectTranslations → 경로 설정 | 필드·라벨·기준값을 코드·Flow·화면이 참조. 선택 목록 값 집합은 필드보다 먼저                                                                  |
| 2    | 보안   | 역할 → 공개 그룹 → Queue → 프로필(최소 파일) → 권한 집합 → 공유 규칙                                                                                                                                                                                                | 공유 규칙이 역할·그룹·필드를 참조. **공유 규칙을 교체할 때는 새 규칙 먼저 배포 → 성공 확인 → 옛 규칙 삭제**(거꾸로 하면 그 사이 접근이 끊김) |
| 3    | 코드   | Apex 클래스·트리거 → LWC → Aura                                                                                                                                                                                                                                     | 1~2단계 필드·라벨·권한 참조                                                                                                                  |
| 4    | 자동화 | Named/External Credential → Flow → 메일 템플릿·알림 유형 → Workflow(필드 업데이트·메일 알림) → 승인 프로세스 → 할당 규칙 → 빠른 작업                                                                                                                                | 승인 프로세스가 Flow·Workflow·메일 템플릿 참조, 빠른 작업이 Flow 참조                                                                        |
| 5    | 화면   | 레이아웃 → 레코드 페이지·홈·유틸리티 바(FlexiPage) → 탭 → 앱(프로필별 홈 지정 포함) → 경로 → 목록 보기 → 앱 내 안내 → 리포트 폴더·리포트 → 대시보드                                                                                                                 | 앱이 FlexiPage·탭을, 홈이 목록 보기·리포트를 참조                                                                                            |

- 권한 집합은 클래스·Flow·탭·외부 자격 증명 보안 주체를 참조하므로, 단계별로 나눌 때는 **코드·자동화 뒤에 권한 집합을 다시 배포**한다

## 4. SFDX 명령

### 4-1. 검증 배포 → 빠른 배포

```powershell
# 0) 로그인
sf org login web -a hg-uat  -r https://test.salesforce.com     # 검증용 샌드박스
sf org login web -a hg-prod -r https://login.salesforce.com    # 운영

# 1) 검증 배포 (대상 org 변경 없음, 로컬 테스트 전부 실행)
sf project deploy validate -o hg-prod --manifest manifest/package.xml --test-level RunLocalTests -w 120

# 2) 빠른 배포 (검증 성공 Job, 10일 안, 그 사이 대상 org 메타데이터 변경 금지)
sf project deploy quick -o hg-prod --job-id <검증 Job Id> -w 60

# 단계별로 나눌 때 (예: 1단계 기반만)
sf project deploy start -o hg-uat -m GlobalValueSet:ServiceCenter -m "CustomObject:ServiceSetting__mdt" --test-level NoTestRun -w 60
```

- `deploy validate`는 `NoTestRun`을 받지 않는다. 테스트 없이 구문만 볼 때는 샌드박스에서 `deploy start --dry-run --test-level NoTestRun`(운영 불가)
- 운영은 테스트 수준 `RunLocalTests`. 관리 패키지 테스트는 제외된다

### 4-2. 실패할 때 확인

| 증상                                                     | 원인                                              | 조치                                                        |
| -------------------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------- |
| 클래스 다수가 "보류 중이거나 진행 중인 작업"             | 예약 작업이 클래스를 참조                         | 2-5대로 해제 → 다시 검증 → 재등록                           |
| "Unknown user permission"                                | 권한이 필요한 org 설정이 꺼짐                     | 설정을 먼저 켜고 다시 배포                                  |
| 공유 규칙 체크박스 조건 값 오류("참" 또는 "거짓"을 사용) | 배포 사용자 언어에 따라 값 표기가 다름            | 배포 사용자 언어가 한국어면 "참", 영어면 "True"로 바꿔 배포 |
| 커버리지 부족(특정 클래스 75% 미만)                      | 단계별 배포에서 그 클래스를 쓰는 테스트를 안 넣음 | `RunSpecifiedTests`에 관련 테스트 추가 또는 `RunLocalTests` |
| 필드·라벨 없음                                           | 단계 순서가 바뀜                                  | 3장 순서대로 앞 단계 먼저                                   |
| 승인 프로세스 사용자 없음                                | AP2 승인자가 개발 사용자 Username                 | 4-3대로 수정                                                |

## 8. 롤백

### 8-1. 이전 커밋으로 재배포

```powershell
# 1) 배포 직전 운영 상태를 같은 manifest로 받아 백업(배포 전에 미리)
sf project retrieve start -o hg-prod --manifest manifest/package.xml --target-metadata-dir backup/hg-prod-<날짜> --unzip
# 2) 문제 시: 이전 릴리스 커밋으로 돌아가 검증 → 빠른 배포
git checkout <이전 릴리스 태그>
sf project deploy validate -o hg-prod --manifest manifest/package.xml --test-level RunLocalTests -w 120
sf project deploy quick -o hg-prod --job-id <검증 Job Id> -w 60
# 3) 이번에 새로 생긴 구성 요소는 destructiveChanges.xml로 삭제 배포
```

| 상황                          | 방법                                                                                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 검증 배포 실패                | 운영 변경 없음 → 원인 수정 후 다시 검증                                                                                                                |
| 빠른 배포 후 기능 문제        | 8-1(이전 커밋 재배포 또는 백업 재배포), Flow는 이전 버전 활성화                                                                                        |

### 8-2. 되돌릴 수 없는 것과 대응

| 되돌릴 수 없는 것                   | 이유                                                          | 대응                                                                               |
| ----------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
