## SC-01 장비 검색 목록 — `assetSearch`

| 항목           | 내용                                                                                                                                                                                                                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 목적           | 전화 접수 때 고객이 말한 고객사·사업장·시리얼로 장비를 빨리 찾고, 반복 고장 장비를 바로 알아봄                                                                                                                                                                                           |
| 배치           | Lightning 앱 페이지(AS 관리 앱의 "장비 검색" 탭)                                                                                                                                                                                                                                         |
| 컴포넌트       | `assetSearch`(부모: 검색어·정렬·페이지 상태 보유) ⊃ `lightning-input`(검색) · `lightning-datatable`(목록) · 페이지 버튼(이전/다음, `N / 총 M쪽`)                                                                                                                                         |
| 열             | 시리얼(`SerialKey__c`, 행 클릭 링크) · 모델 · 고객사 · 사업장 · 센터 · 보증 상태(`fmWarrantyStatus__c`) · 최근 접수일(`LastCaseDate__c`) · 최근 90일 접수(`RecentCaseCount__c`) · **반복 고장**(`RepeatFailure__c` → 빨간 경고 아이콘 + 행 강조)                                         |
| 검색           | 한 칸 입력 → **고객사명·사업장명·시리얼** LIKE 검색 (접수 번호는 검색 대상 아님). 입력 후 300ms 디바운스, 2글자 이상부터                                                                                                                                                                 |
| 정렬           | **기본: 최근 접수일 내림차순, 접수 없는 장비는 맨 뒤** (`ORDER BY LastCaseDate__c DESC NULLS LAST, SerialKey__c`). 열 머리글 클릭(`onsort`) → 서버 정렬. 허용 필드 화이트리스트(시리얼·고객사·최근 접수일·최근 90일 접수·보증 상태)만, 날짜·숫자 정렬은 항상 NULLS LAST                  |
| 페이징         | **20건 고정**, 서버 `LIMIT/OFFSET` (OFFSET 최대 2,000 → 장비 수 증가 시 키셋 페이징으로 전환)                                                                                                                                                                                            |
| 데이터         | **imperative** 호출 — 검색·정렬·페이지 이동이 모두 사용자 동작이라 호출 시점을 컴포넌트가 정함. 메서드는 `cacheable=true`로 같은 조건 재조회는 캐시                                                                                                                                      |
| Apex           | `AssetSearchController.searchAssets(String searchKey, String sortField, String sortDirection, Integer pageNumber)` → `AssetSearchController.AssetPage`(rows, totalCount). 페이지 크기는 컨트롤러 상수 `PAGE_SIZE = 20`. 검색어는 바인드 변수, 정렬 필드는 화이트리스트(SOQL 인젝션 방어) |
| 행 클릭        | `NavigationMixin`으로 장비 레코드 페이지(SC-04가 배치된 페이지)로 이동                                                                                                                                                                                                                   |
| 빈 결과 / 오류 | 결과 0건: "검색 결과가 없습니다. 고객사명·사업장명·시리얼을 확인하세요."(`MSG_ASSET_NOT_FOUND`) / 오류: 토스트 + 목록 유지 / 로딩: `lightning-spinner`                                                                                                                                   |

- **2026-10-15 변경(CTI)**: 시리얼을 누르면 장비 상세로 바로 가지 않고 **장비 요약 팝업(SC-09)**을 엶 → [장비 열기]로 상세, [이 장비로 접수]로 접수 작성 팝업(SC-08)

## SC-xx 출동 사용 부품 (D8 스케치)

```
workOrderParts (부모, 출동 레코드 페이지, @api recordId)
 ├─ 사용 부품 목록 (lightning-datatable: 부품·수량·자동 판정·최종 판정·금액) + 합계(유상 부품비) + 승인 필요 표시(fmNeedsApproval__c)
 └─ partAddForm (자식): 재고 선택 + 수량 → 저장(imperative, DML이라 cacheable 불가)
       └─ 저장 성공 시 CustomEvent('partadded', { detail: { partId } }) → 부모
부모: onpartadded → refreshApex(목록·합계) → 판정 결과 토스트 ("보증 내 무상" / "유상")
```

- 저장은 트리거가 유·무상을 판정하므로 화면은 수량·재고만 받음. 사유 입력은 최종 판정을 바꿀 때만 표시
- 기사 사용자로 동작해야 함 → 컨트롤러는 `with sharing` + 기사 차량 재고만 조회 (D6에서 발견한 API 67.0 user mode 결함 참고)

## SC-05 사업장 등록 — `customerSiteNew` (D8, 새로 만들기 재정의)

- 진입: 사업장 탭·고객사의 사업장 관련 목록 "새로 만들기"(데스크톱). Aura 래퍼 `customerSiteNewOverride`가 표준 버튼을 대신함. 전체 페이지
- 왼쪽 사업장 정보(record-edit-form): 고객사(관련 목록에서 열면 자동 입력) · 사업장명 · 용도 · 담당 서비스센터(표시만) · 현장 담당자·연락처 · 출입 조건 · 작업 가능 시간 · 계약 SLA
- 오른쪽 주소(필수): 공통 `addressSearch` → 선택한 주소 + 상세주소. 서비스센터는 고르지 않음 — 주소로 지정될 센터를 표시만, 저장 시 트리거가 매핑으로 채움. 주소 미선택·매핑 없음이면 저장 막음 (2026-10-14 센터 완전 자동)
- 저장 → 새 사업장으로 이동, 취소 → 고객사(관련 목록에서 연 경우) 또는 사업장 목록, 오류 → 토스트

## SC-06 고객사 등록 — `accountNew` (D8, 새로 만들기 재정의)

- 진입: 고객사 "새로 만들기"(데스크톱) → 표준 레코드 유형 선택 → Aura 래퍼 `accountNewOverride` → 전체 페이지. 주소로 바로 열어 유형이 없으면 화면에서 "고객 유형"부터 선택
- 제목에 유형 표시(예: 고객사 등록 · 법인). **개인은 사업자번호 숨김**, 형식·대리점 규칙은 기존 검증 규칙
- 왼쪽: 고객사명 · 사업자번호 · 전화 · 거래 상태 · 고객 등급 / 담당자·결제: 청구 담당자명·연락처·이메일 · 결제 방식
- 오른쪽 청구지 주소: 공통 `addressSearch`. 국가 KR · 시도 비움 · 시 = 시군구 · 번지 = 도로명주소(+상세주소, 참고항목) · 우편번호
- 저장 → 새 고객사로 이동, 취소 → 고객사 목록, 오류 → 토스트

## 장비 이름 · 시리얼 (D8)

- 장비 이름은 자동 생성: 모델/고객사/사업장/시리얼 끝자리 (예: HAC-300/(주)국민마트/국민마트 2창고/0001). 저장할 때마다 다시 만들고, 사업장·고객사 이름이 바뀌면 그 장비들도 바뀜
- 시리얼 키는 일련번호와 같은 값으로 자동, 레이아웃에서 숨김. SC-04 장비 상세는 "일련 번호" 표시
- 이름 읽기 전용은 레이아웃 제약으로 보류 (decision-log 장비 이름 #5)

## SC-10 출동 승인 요청 — Screen Flow `WorkOrder_Screen_RequestApproval` (2026-10-15, 데스크톱)

출동 레코드 페이지 강조 패널의 빠른 작업 **[승인 요청]**(표준 "승인 요청" 버튼은 레이아웃에서 제거). 실행: 기사(HG_Technician)·관리자

| 화면                | 조건                                   | 내용                                                                                                                                                                                                                                                                                                         |
| ------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 이미 승인 대기 안내 | 상태 PendingApproval                   | "이미 센터장 승인 대기 중입니다…" [마침]                                                                                                                                                                                                                                                                     |
| 도착 상태 아님 안내 | 상태 ≠ Arrived                         | "도착(Arrived) 상태인 출동만 승인 요청할 수 있습니다. 현재 상태: …"                                                                                                                                                                                                                                          |
| 승인 불필요 안내    | 예외 무상 없음 + 청구 합계 ≤ 기준 금액 | "승인이 필요하지 않습니다" + 청구 합계 / 기준 금액                                                                                                                                                                                                                                                           |
| 승인 요청 입력      | 그 밖                                  | **승인이 필요한 이유**: 예외 무상 부품 N건 · 청구 합계 / 승인 기준 금액(ServiceSetting ApprovalAmount) · 기준 초과면 빨간 안내 / **승인 요청 사유**(필수, 255자) / **고객 유상 동의**(기준 초과일 때만 보임·체크해야 진행) / **센터장에게 남길 메모**(선택, 승인 요청 코멘트로 전달, 필드 저장 안 함) [다음] |
| 승인 요청 완료      | 제출 성공                              | "센터장에게 승인 요청을 보냈습니다…" (상태 → PendingApproval, 승인자 = 기사의 Manager)                                                                                                                                                                                                                       |
| 승인 요청 실패      | 승인 프로세스 진입 조건 불일치 등      | 실패 문구 + 플랫폼 메시지, **저장한 사유·동의도 되돌림**                                                                                                                                                                                                                                                     |

- 저장·제출은 하위 Flow `WorkOrder_Sub_SubmitApproval`(Apex 테스트 대상). 승인 여부 판단은 승인 프로세스 진입 조건이 최종
