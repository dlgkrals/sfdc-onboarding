## 1. 재고 선택: 조회 필드 → 담당 기사 차량 재고 목록

| 항목      | 내용                                                                                                                                                                                                  |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 바꾼 이유 | 표준 조회 필드는 재고 번호(PI0001)로 찾아야 해서 기사가 어떤 재고인지 알 수 없고, 다른 위치(창고·다른 차량) 재고를 고를 수 있음                                                                       |
| 보이는 것 | 이 출동 **담당 기사 차량의 재고만**, "부품 이름 · 위치 · 남은 수량(단위)" (예: `냉매 R-404A · 최민호 차량 · 16.5 kg`)                                                                                 |
| 빈 재고   | 남은 수량 0도 목록에 보이되 **고를 수 없음**(`(재고 없음)`). 숨기면 "왜 안 보이지?"가 됨                                                                                                              |
| 데이터    | `WorkOrderPartsController.getVanStock` — `@AuraEnabled(cacheable=true)`, `with sharing` + `WITH USER_MODE`. 출동 소유자(담당 기사)의 차량(LocationType = Van) 재고, 남은 수량 0이면 `available=false` |
| 받는 방식 | `@wire` — 출동 Id만으로 정해지는 조회(사용자 동작 없음). 저장 뒤 남은 수량이 바뀌므로 `refreshApex`로 다시 읽음                                                                                       |
| 저장      | `addPart` imperative (DML이라 cacheable 불가). **서버에서도** 남은 수량 0인 재고는 거부(`MSG_STOCK_EMPTY`) — 화면 비활성은 우회할 수 있으므로                                                         |
| 화면 요소 | `lightning-combobox`는 항목별 비활성이 없어 SLDS select(`slds-select`) 사용. 선택 안 함은 `slds-has-error` + 도움말로 표시                                                                            |

## 2. partadded 이벤트: bubbles · composed

```js
this.dispatchEvent(
  new CustomEvent("partadded", {
    detail: { partId },
    bubbles: false,
    composed: false
  })
);
```

| 설정      | 값             | 이유                                                                                                                                        |
| --------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| bubbles   | false (기본)   | 부모가 `<c-part-add-form onpartadded={handlePartAdded}>`로 **자식 요소에 직접** 리스너를 닮 → 위로 퍼지지 않아도 받음                       |
| composed  | false (기본)   | 켜면 그림자 DOM 경계를 넘어 부모 바깥(레코드 페이지의 다른 컴포넌트)까지 새어 나감 → 같은 이름을 쓰는 곳이 의도치 않게 받을 수 있음         |
| 언제 켜나 | bubbles만 true | 부모 template 안에서 자식 여러 개의 이벤트를 상위 div 한 곳에서 받을 때. composed까지 켜는 경우는 드묾(컴포넌트 밖 컨테이너가 받아야 할 때) |
| detail    | `{ partId }`만 | 유·무상 판정은 트리거가 하므로 부모가 저장된 결과를 서버에서 다시 읽음. 화면 값을 넘기면 판정과 어긋날 수 있음                              |

## 4. 결정 반영 (2026-10-14, decision-log 18)

- 출동 페이지 표준 "사용 부품" 관련 목록의 **새로 만들기 버튼 숨김**(목록은 유지). 확인: 레이아웃 describe에서 관련 목록 버튼 0개
- **남은 수량 초과 입력 거부**: 화면은 수량 칸 `setCustomValidity`로 "차량 재고가 부족합니다(남은 n단위). 창고에서 재고 이동으로 먼저 채워 주세요.", 서버 `addPart`도 같은 문구로 거부. 정확히 남은 수량은 허용
- 테스트 11개: 초과 입력 거부(불허) · 정확히 남은 수량 허용(경계) 추가
